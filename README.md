# 日程卡片 Schedule Cards

> **在线使用（推荐，支持跨设备同步）：https://rc.wbztl.xyz/**
> 备用地址：https://schedule-cards.vercel.app/
> 旧的 GitHub Pages 地址 https://fjkkx77.github.io/Schedule-Cards/ 仍可打开，但**没有同步功能**
> （同步要靠 Vercel 上的接口，GitHub Pages 只能放静态文件）

一个单文件网页（`index.html`），双击就能用，不需要联网、不需要安装任何东西。
设一个日期，**自己选**是从这天起往后正数，还是距这天倒数。

---

## 一、怎么用

1. 双击 `index.html`，用浏览器打开（手机上把这个文件发给自己，用浏览器打开也一样）。
2. 点右下角蓝色 **＋** 新增一条日程：
   - **事件名称**：比如「回家过年啦」「四级」
   - **计算方式**：三选一，见下面第二节
   - **日期**：点一下弹出日历选择器（年/月 下拉 + 「今天」+ 点日期格 + 取消/完成），
     倒数时标签是「目标日期」，正数时是「起算日期」
   - **或直接填天数**：日期下面一行「或直接填：还有 [ 21 ] 天」，填数字就自动算出日期，不用自己数日历。
     倒数 = 今天 + N；切到正数时变成「已经 [ N ] 天」= 今天 − N。和日期是双向的：选了日期，这里就显示卡片上会出现的那个数
   - **按日历算天数 / 不含到期当天**（只有倒数、自动时出现）：会员、订阅这类 App 写着「9月25日到期」，
     通常 25 日当天就失效了，所以显示的剩余天数比日历少 1 天（QQ 会员 9月17日显示「还有 7 天」，按日历算是 8 天）。
     打开这个开关后卡片按 App 的口径显示；这时填「还有 21 天」会自动把日期定在今天 + 22，卡片上正好显示 21
   - **具体时刻（可不填）**：日期下面可以选「时 : 分」，比如考试 09:00、发车 14:35。
     填了倒计时就按这个点算，不填按当天 00:00 算（和以前完全一样）。旁边有「清除」
   - **实时倒计时**：选好日期后，下面会显示「还剩 3 天 12:05:08」并逐秒跳动。
     **基准写在第二行**（填了时刻就是「距 2026-12-12 09:00」，没填就是 00:00）。颜色随紧迫度变：7 天内变橙、24 小时内变红；
     当天显示「就是今天 · 还剩 xx:xx:xx（距今天结束）」；过期显示「已过 …」；正数显示「已经 …」
   - **分组**：一行三个入口 —— 「不分组」、**中间的下拉（已有分组都收在里面，选中后按钮直接显示它）**、
     「＋ 新建分组」。已有分组不管多少个，这一行都只占一行高，不会换行把表单撑长；
     一个分组都没有时中间的下拉不出现
   - **颜色**：6 个色，卡片顶栏和列表色块跟着变
   - **置顶**：一个开关按钮，点一下在「未置顶 / 已置顶」之间切换
   - 点 ＋ 后光标**直接落在「事件名称」里、手机键盘自动弹出**，不用再点一下输入框
3. **点任意一张卡片 / 一行**就能编辑。弹窗底部：取消（左）/ 保存（右）同一排，
   「删除这条日程」单独一行在它们下面。
4. **左滑一张卡片 / 一行**，右边露出两个按钮（淡色调：浅蓝底蓝字 / 浅红底红字 + 线条图标，不跟卡片抢眼；深浅色各一套，文字对比度都 ≥4.5）：
   - **置顶**（已置顶的显示「取消置顶」）：点一下立刻生效，卡片挪到置顶区并闪一下
   - **删除**：弹出「删除「xx」？」确认，确认后才删（和编辑弹窗里的删除一样走墓碑，能同步）
   - 滑一小段松手会弹回去；滑开后**点这张卡、点别的卡、或滚动页面**都会收回，这一下不会误进编辑
   - 卡片视图 / 列表视图、置顶区、**展开的**分组里都能滑；**收起的一摞不能滑**（一摞只露一张，滑的是哪条说不清，先点开再滑）
   - 屏幕左右边缘 28px 内起手不算，留给手机系统的前进/返回手势
5. **手机上往下拉就能关掉弹窗**（编辑日程、云同步、重命名/删除分组、删除确认都支持；顶部那根小横条就是提示）：
   - 弹窗跟着手指往下走，拉过弹窗高度的约 22%（至少 80px、最多 160px）或者快速往下一甩就关，不够就弹回
   - **改了东西没保存时不会直接关**，先问「放弃这次修改？」——继续编辑 / 放弃修改。点「取消」按钮的老路径不变
   - 弹窗内容往下滚过了、在时/分等下拉列表里、日期选择器开着时，往下拉都不会关（那是在滚内容）
   - 为什么是下拉不是右滑：苹果对这种从底部弹出的弹窗（sheet）规定的就是上下滑关闭；
     网页里从左边缘右滑是浏览器自己的"返回"，网页抢不到，一划会直接退出网站

> **2026-09-09 去掉了「每年重复」**。生日 / 纪念日这类日程，过了当天会显示成「已过期 N 天前」，
> 不再自动跳到下一年 —— 需要的话每年手动改一次日期，或者把计算方式设成「自动」。

## 二、计算方式：正数 / 倒数 / 自动

| 选项 | 含义 | 例子（今天 = 9月8日） |
|---|---|---|
| **倒数** | 距离这一天还剩多少天 | 目标 12月2日 → **85 天** |
| **正数** | 从这一天起，往后一共累计过了多少天，每天 +1 | 起算 9月8日 → 今天显示**今天开始**，明天 **1 天了** |
| **自动** | 日期在未来就倒数、在过去就正数，由日期自己决定 | —— |

选了之后各种情况分别长这样：

| 情况 | 显示 |
|---|---|
| 倒数 · 还没到 | `124 天` |
| 倒数 · 就是今天 | `就是今天` |
| 倒数 · 已经过了目标日 | `7 天前` ＋ 红色「已过期」标签（卡上别的标签如「原属 XX」退成灰色，只留这一个是红的），**整张卡褪灰**（顶条变成浅灰斜纹、深色字，标题和数字变浅；列表视图数字块同样是斜纹）。用斜纹而不是实心灰，是为了不和颜色板里的深灰色撞（见下面第十节） |
| 倒数 · 不含到期当天 · 到期前一天 | `最后一天` |
| 倒数 · 不含到期当天 · 到期日当天 | `今天到期`，**不算过期**（不褪灰，也不计入首页过期提示），第二天起才算过期。2026-09-26 改：原先当天就褪灰 |
| 正数 · 起算日已过 | `7 天了` ＋「已累计」标签 |
| 正数 · 起算日就是今天 | `今天开始` |
| 正数 · 起算日还没到 | `85 天后` ＋「未开始」标签，数字变灰 |

数字下面那一行会写清楚是「目标 2027-01-10 星期日」还是「起算 2026-09-01 星期二」，
不用担心看不出来这条到底是正数还是倒数。

> **正数没有「过期」**：正数就是一天天往上加。「自动」模式的日期一过就转成正数「N 天了」，同样不会褪灰。

**过期汇总（2026-09-26）**：分组默认叠成一摞，压在下面的过期卡从外面看不见，所以首页加了一个入口。

- 有过期的日程时，工具条下面出现一条淡红提示「❗ N 个日程已过期　查看 ›」；**没有就整条不出现**
- 算进去的 = 上表里褪灰的那些：倒数且已过了目标日（置顶的也算；正数、自动转正数、「今天到期」都不算）
- 点进去是**主页切换成「只看已过期」**，不是另开页面：平铺、不分组不叠放，**刚过期的在最上面**，
  卡片上标出原来属于哪个分组；工具条和＋暂时隐藏。点卡片直接编辑（比如改日期顺延），左滑可以置顶/删除
- 退出：点右上「完成」，或者浏览器返回（Safari 左边缘右滑）。回到主页时滚动位置还原；在这个视图里下拉刷新会留在这个视图
- 这个视图里不能长按拖动排序（只是筛出来的一部分，拖了会把整体顺序改乱）
- 没有做「一键清空全部过期」：误删代价太大，先用左滑逐条删，真嫌麻烦再加（加的时候要二次确认、走墓碑）

## 三、两种显示样式

顶部「卡片 / 列表」随时切换，切换后的选择会被记住：

| 样式 | 长什么样 |
|---|---|
| **卡片** | 彩色顶栏写今天的日期，格子纸底纹，左边事件名+目标日期（有时刻就带上）+**下面一行农历**，右边超大天数（比例数字，三位数字距再收紧一点——只收窄不缩小） |
| **列表** | 一行一条，左边事件名，右边彩色天数色块，适合一屏看很多条。**每个分组、每条没分组的日程各有一个圆角框**，分组标题在框外（像 iPhone「设置」；2026-09-26 用户选的，原先除置顶外全挤在一个大框里，没分组的那条看着像是上一组的）。「只看已过期」里仍是一个框 |

## 四、农历

顶部的今天、以及编辑弹窗里选好的日期，下面都会显示农历（如「农历七月廿八」）。

数据表取自 [data-Calculation](https://github.com/fjkkx77/data-Calculation)，
它是用**香港天文台《公曆與農曆日期對照表》1901-2100 逐日文本**生成并全区间比对过的。
**没有用浏览器内置的农历**——那个在这 200 年里有 12 段临界日算错，其中就包括 2027 年春节
（正确是 2 月 6 日，浏览器会算成 2 月 7 日）。超出 1901-2100 的日期不显示农历，不外推。

## 五、分组（堆叠卡片）

**分组标题**是一行小节标题：名字 18px 深色字，前面一根分组颜色的短竖条，后面是白色小圆牌里的条数（和最早的样子一样）、⋯ 和箭头。
竖条颜色取这个分组在「自定义顺序」里排第一张卡片的颜色，所以**切换排序不会变色**；
置顶区标题同样有一根，取置顶区第一张的颜色。分组与上面的内容之间多留 10px。

在新增/编辑弹窗里给日程填一个**分组**名（比如「考试」「生活」），留空就是不分组。
下面会列出已有的分组，点一下就能填进去，不用重复打字。

同一分组的日程会**叠成一摞**：

- **收起时**只露出最上面一张，后面每张**真的往屏幕里退**（CSS 3D 透视，不是单纯缩放），
  越往后越小、越暗、还带一点随手叠上去的歪斜，第三层再加一点虚化景深
- **按住这一摞**会整体往里压一下，松开才展开，手感像真的按到一叠卡
- **点这一摞的任意位置，或点分组标题**，卡片会依次错开 62ms 弹出来，
  带轻微过冲回弹（实测第二张位移 130px、宽度 315→367，冲到 178.6 再落回 176）
- **展开后再点某一张**才是编辑那一条 —— 收起状态下点它是展开，不会误触进编辑
- 分组标题右边的圆形箭头指示当前是收起还是展开
- 每个分组的展开/收起状态会被记住，下次打开还是你离开时的样子
- 最上面那张永远是**当前排序里排最前**的那条（比如按天数临近时，就是最紧急的那条）
- 卡片视图和列表视图都能堆叠；一个组里只有一条时不堆叠，直接点就是编辑
- 新建日程时如果填了分组，那个分组会自动展开，免得存完找不到
- **在主页管理分组**：点分组标题右边的「⋯」→ 重命名 / 删除。
  菜单底部有一行灰字提示，随当前排序变文案：
  - 「自定义顺序」下 → 「长按分组名可以直接拖动排序」
  - 其它排序下 → 「想自己排顺序：先把上面的排序切到「自定义顺序」，再长按分组名拖动」
    （长按在这些排序下本来就拖不动，不解释一句容易让人以为坏了）
  - 排顺序不给按钮，长按拖就够了；这行字只是把这个手势说出来，免得没人知道

  删除有两种，默认走安全的那种：
  - **解散分组**（左边蓝色）：里面的日程全部保留，只是变成「不分组」
  - **连同日程一起删**（右边红色）：会二次确认；走和单条删除一样的墓碑机制，能同步到另一台设备
  - 取消在这两个按钮下面单独一行
  - 重命名时如果新名字和已有分组重名，两个分组会合并（弹窗里有提示）

## 六、置顶 与 拖拽排序

**置顶**：编辑弹窗里把「置顶」打开即可。

- 置顶的日程**不管当前用哪种排序都排在最上面**，单独放在「📌 置顶」区
- 置顶区**不堆叠**，全部平铺 —— 置顶的目的就是一眼看见，再折起来就自相矛盾了
- 如果这条日程属于某个分组，置顶后会**暂时离开那个分组**（分组条数相应减 1），
  卡片上会标出「原属 XX」告诉你它本来在哪；取消置顶自动回去

**拖拽排序**（只在「自定义顺序」下）：**长按 0.45 秒**把卡片拿起来，拖到想去的位置松手。

- 三个地方都能拖：置顶区内、展开的分组内、顶层（未分组的卡片之间；
  **长按分组标题可以把整个分组挪位置**，组内日程的顺序跟着整体搬走）
- 短按还是原来的意思：收起的分组 → 展开；其它 → 打开编辑窗。长按才是拖
- 拖动期间下拉刷新自动让位，不会拖着拖着把页面刷新了

## 七、其他功能

- **排序**（5 种）：
  - 自定义顺序（长按拖动可调整）
  - 按天数临近
  - 按日期先后
  - **按创建时间**：先建的排前面
  - **按最近修改**：最近改过的排前面
  - 排序对分组同样有效：组内按它排，组与组之间按各自最靠前的那条排
- **⋯ 菜单**：
  - 列表显示日期：列表样式下要不要在事件名下面带一行目标日期
  - 主题：跟随系统 / 浅色 / 深色
  - **导出备份 / 导入备份**：导出一个 `.json` 文件，换手机换电脑时导入即可
  - 清空全部日程
- **跨零点自动刷新**：页面开着过了零点，天数会自动 −1，不用手动刷新

## 七½、短期倒计时（2026-09-26）

给「今天下午三点开会」「30 分钟后泡面好了」这种**一天之内**的事用，秒级地看着它走。
**和日程卡片完全隔离**：自己的数据、自己的同步分区，日程卡片的数据、计算规则、显示一样都没动。

- **入口**：右上角 ⋯ 旁边的 ⏱ 按钮（用户从四套里选的「右上角按钮 + 数量」）。
  角标数字 = 进行中 + 已超时的条数，**有超时时变红**；没有就不显示。进入后按钮变蓝，再点一下或点「完成」回到日程；
  浏览器返回（Safari 右滑）也能回去，在里面下拉刷新会留在里面
- **显示**：「2 小时 04 分 59 秒」逐秒跳动（小时不补零、分秒固定两位——等宽数字下宽度不跳，不会左右抖）。
  进度条 = 从开始到现在走了多少；**10 分钟内数字变红**
- **颜色**（2026-09-26 用户嫌太素，从三套里选的「B 白卡 + 左侧彩色竖条」）：每条有自己的颜色（和日程同一套 6 色，新建时按条数轮换，也能自己选），
  左侧竖条和进度条用这个色，数字是「卡片色往文字色里混 22%」——浅色下略深、深色下自动变亮（6 种颜色两种主题对比度都 ≥ 3）
- **分区**：已超时（淡红，刚超时的在上，右边一个「知道了」）→ 进行中（先到的在上）→ 已结束（折叠）
- **过点之后**（用户定的规则）：先显示红色「已超时 xx 分 xx 秒」并继续正计 → 点「知道了」归入「已结束」→
  **第二天自动清掉**（已结束 / 超时没管的，结束时间早于今天 0 点就清）。清理和删除都走墓碑
- **添加**：点右下角 ＋（在这个界面里 ＋ 是「新的倒计时」）。只要名称（可不填）+ 二选一：
  「多久后」15 分钟 / 30 分钟 / 1 小时 / 2 小时 / 自定义几小时几分；「到点」选个钟点（**今天已过的钟点自动算明天**）。
  下面实时写着「将在 今天 17:01 到点，还有 30 分钟」。不填名称就用时长或钟点当名字
- **点一条 = 编辑**（2026-09-26 起；原先只能延后/删除，用户反馈设错了改不了）：名称、时间、颜色都能改。
  **只改名字/颜色时到点时刻不变**；动了时间才重新计时（进度从现在算）。弹窗顶部是常用动作：
  进行中 → 延后 10 / 30 分钟、提前完成；已超时 → 知道了、延后、再来一次；已结束 → 再来一次。最下面是删除（先确认）
- **左滑**：置顶 / 删除，和日程卡片同一套按钮（用存档组件 `SwipeActions`）。置顶的进「📌 置顶」分区；已结束的只能删；删除先确认
- **屏幕常亮**：标题行的「☀ 常亮」，看倒计时时屏幕不会自动锁。用的是 Screen Wake Lock，
  iOS Safari 16.4 起支持（依据：caniuse 与苹果 WebKit 的 Safari 16.4 发布说明）；浏览器不支持时按钮不出现。
  切走页面会被系统自动释放，回来时自动重新打开。这个开关是每台设备自己的，不同步
- **不会到点响铃 / 推送**：只负责「打开就能看到」
- 数据存在本机 `schedule-cards-short-v1`；**不在「导出备份」里**（导出的只是日程）

## 八、跨设备同步（手机 ↔ 电脑）

打开 **⋯ → 云同步**，填一个**同步码**（可以点「随机生成一个」），点「开启并同步」；
在另一台设备上填**同一个同步码**，两边的日程就自动互通了。

- 同步码相当于密码，**知道它的人就能看到并修改这些日程**，别外传。服务端只存它的 sha256 哈希
- 只同步日程本身。视图（卡片/列表）、排序、主题、分组展开状态是每台设备自己的偏好，不同步
- **短期倒计时也用同一个同步码**，但存在服务端**另一份**数据里（`space=short`，存储键 `sched:short:<哈希>`），
  和日程互不相干，各自计版本号。合并规则一样（按 id + 修改时间、删除走墓碑）。
  客户端会核对服务端回传的 `space`：万一服务端还是旧版（它会忽略这个参数、把日程还回来），短期那份直接跳过，
  **绝不会把倒计时写进日程里**——这一条做过变异测试（去掉核对后倒计时确实被写进了日程那份）
- **什么时候会同步**：打开页面 / 从后台切回页面 / 窗口获得焦点 / 网络恢复 /
  每 30 秒（仅在页面可见时）/ 本地改动后 1.2 秒
- **这是秒级同步，不是即时推送**：手机上改完，电脑那边要切回页面或最多等 30 秒
- **合并规则**：按条目 id 取并集，同一条取修改时间更新的那份。
  删除是打「墓碑」标记而不是真删（否则另一台设备会把删掉的当新条目加回来），墓碑保留 120 天
- 两台设备同时改也不会丢东西：写入带版本号，冲突时自动重新合并并重试
- 顶部会显示同步状态（已同步 / 同步中 / 失败原因）
- **开启同步后，没被你编辑过的示例数据会自动退场**（不上传、本地也清掉）。
  因为示例在每台设备上「看着一样但内部 id 不同」，参与合并只会变成每条两份。
  你动过的示例卡片就算你自己的数据，照常同步

技术上：Vercel Functions（`api/sync.js`，零依赖）+ Upstash Redis。
免费额度 500K 命令/月、256MB、10GB 流量，这个用量下用不掉零头。

## 九、数据存在哪（重要）

**没开同步时**：数据只存在**当前这个浏览器**的本地存储里（localStorage）。也就是说：

- 换浏览器、换设备、清理浏览器缓存/网站数据 → **数据会丢**
- 重要的日程，请用「⋯ → 导出备份」存一份 json 文件

**开了同步后**：数据同时存在本机和云端；换设备只要填同一个同步码就能取回。
但导出备份仍然值得做——同步码丢了、或者误删了全部日程，本地备份是最后一道保险。
